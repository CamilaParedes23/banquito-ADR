# Ciclo de vida de ADR

1. **Propose:** un ASR, riesgo o cambio estructural genera una decisión candidata.
2. **Contrast:** se comparan alternativas, costos, riesgos y trade-offs.
3. **Accept / Reject:** se aprueba o descarta la dirección.
4. **Implement:** se materializa en código, infraestructura o documentación.
5. **Verify:** se adjunta evidencia reproducible.
6. **Supersede:** si cambia la decisión, se crea un ADR nuevo y se preserva el anterior.

## Estados de decisión

- `Proposed`: bajo análisis.
- `Accepted`: dirección aprobada y vigente.
- `Rejected`: propuesta descartada o registro reclasificado con disposición explícita.
- `Superseded`: reemplazado por otro ADR.

## Estados de implementación

- `Not started`
- `In progress`
- `Implemented`
- `Verified`
- `Not applicable`

No confundir ambos ejes: un ADR puede estar `Accepted` e `In progress`.
